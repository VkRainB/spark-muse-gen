# spark-muse-gen 产品设计优化方案（工具/页面归类 + 弹层显示不全修复）

## Context

`spark-muse-gen` 是基于 Gemini 3 Pro 的 AI 图像生成工作台（Nuxt 4 + Vue 3 + Nuxt UI v4 SPA）。当前左侧侧边栏的 5 个"创作工具"卡片在产品形态上不一致——4 个走 `UModal` 居中弹层、1 个（XHS）走独立页面 `/xhs`，用户在卡片视觉一致的前提下点击后行为却不同，造成认知摩擦；同时弹层内多处出现"显示不全"现象，根因是嵌套滚动 + 子组件硬编码高度限制（`max-h-96`、`min-height: 480px`、`max-height: 45vh`）。

本方案从产品/信息架构层面给出"何时用页面、何时用抽屉、何时用居中弹层"的判断准则，对 5 个工具入口与设置入口做重新归类，并给出弹层显示不全的产品层修复策略。代码实施细节由后续 PR 独立排期。

---

## 一、产品判断准则（做归类的依据）

| 编号 | 判定指标 | 倾向结论 |
|------|----------|----------|
| C1 结果是否回流主流程 | 产出是塞回主聊天输入的"中间态"，还是独立可下载/可保存的"终态" | 中间态 → 弹层；终态 → 页面 |
| C2 单次会话时长 | <2 min 的"挑一下/查一下"操作，还是 >5 min 的多轮迭代工作流 | 短任务 → 弹层；长工作流 → 页面 |
| C3 状态持久化需求 | 关闭后状态是否需要保留（store / localStorage / 历史记录） | 有持久化 → 页面；纯瞬态 → 弹层 |
| C4 信息密度 | 是否需要 ≥3 个并列功能区（列表 + 编辑 + 预览/历史） | 三栏 → 页面；单/双栏 → 弹层/抽屉 |
| C5 主流程依赖度 | 是否需要边看主聊天上下文边操作 | 边看边操作 → 抽屉；上下文无关 → 居中弹层或页面 |

**总则**：居中 Modal 仅给"短、轻、回流且对称"的单次工具；抽屉/Slideover 给"伴随主流程、需要瞥一眼上下文"的辅助面板；页面给"长、重、独立产物"的工作台。

## 二、功能归类最终决策（已与用户对齐）

| 功能 | 当前形态 | 推荐形态 | 命中准则 | 依据 |
|------|----------|----------|----------|------|
| XHS 灵感实验室 | 页面 `/xhs` | 维持页面 | C2 + C3 + C4 | 三栏长工作流，`stores/xhs.ts` 已持久化历史 |
| Banana 提示词快查 | UModal | 改为右侧 USlideover | C1 + C5 | 短查询、结果回流主聊天，与 `QuickPromptPanel` 体感统一 |
| Custom 我的提示词 | UModal | 改为右侧 USlideover | C1 + C5 | CRUD + 回流主流程，性质同 Banana |
| Sticker 制作表情包 | UModal | 提升为页面 `/sticker` + 加持久化 | C1 + C2 + C3 + C4 | 批量生成独立产物，当前仅存内存是缺陷 |
| Slicer 图片切片 | UModal | 维持居中 UModal（仅瘦身/规约） | 上传→切→下 ZIP | 闭环短、无持久化需求、上下文无关 |
| 设置 SettingsPanel | 右抽屉 + 死路由 `/settings` | 维持右抽屉，删除死路由 | C5 | 全局偏好天然伴随主流程 |

**关键决策说明**：
- **Sticker 升页面**：当前 `generatedStickers` 只存在 `StickerMode.vue` 组件 ref 内（行 9），关闭弹层即丢；批量生成属于终态产物，应该有持久化（新增 `stores/sticker.ts`）+ 更宽的工作区。
- **Banana / Custom 改抽屉**：与已有的 `USlideover`（`pages/index.vue` 行 151-163 的快捷提示词抽屉）形态对齐，达成"提示词类工具 = 右抽屉"的语义一致性。

## 三、左侧导航 IA 调整：视觉分组 + 形态微图标

侧边栏保留扁平结构但按"心智层级"显性分组，并在卡片右上角加微图标提前表达跳转/抽屉/弹层语义，让用户在点击前就能预判"会不会离开主聊天"。

```
[新建对话]

工作台（页面，整页跳转）
  Chat                         -> /            （隐式默认）
  XHS 灵感实验室   ↗            -> /xhs
  表情包工坊       ↗            -> /sticker    （新提升）

工具（伴随主聊天，不离开当前上下文）
  提示词快查        ▢          -> 右抽屉 USlideover
  我的提示词        ▢          -> 右抽屉 USlideover
  图片切片          ◰          -> 居中 UModal

最近对话
  ...

[底部] 设置 ⚙        ▢          -> 右抽屉
```

**形态微图标语义约定**：
- `↗` 跳转独立页面
- `▢` 右侧抽屉（伴随主流程）
- `◰` 居中弹层（独立短任务）

**对单一工具弹层导航方案的否决理由**：把侧栏所有入口收拢到"打开工具集"一个总按钮，再弹一层选具体工具——会把决策成本前置，点击层级翻倍，且工具集面板自身仍要解决"内层滚动/截短"问题，并未触及根因。视觉分组 + 微图标在不增加点击成本的前提下消解了"卡片视觉一致但行为不一致"的认知摩擦。

## 四、弹层显示不全的修复策略（产品层）

### 4.1 抽统一壳：`ToolPanelShell`

定义工具面板的唯一权威骨架，所有工具（含未来新工具）必须套此壳：

```
ToolPanelShell
├─ Header  (标题 / 关闭 / 操作槽)
├─ Body    (唯一滚动容器, flex:1, min-height:0)
└─ Footer  (粘性主操作 CTA, sticky bottom)
```

由 Shell 单点决定"可用高度 + 滚动容器位置"，子组件不再各自规定高度。

### 4.2 子组件高度自适应规约（产品契约，4 条铁律）

所有工具内部组件必须遵守，违反即视为不合规：

1. **禁止固定 max-height / min-height**——必须移除：
   - `BananaTool.vue` 行 90 的 `max-h-96 overflow-y-auto`
   - `CustomPromptTool.vue` 行 312-317 的 `min-height: 480px`
   - `CustomPromptTool.vue` 行 451-458 媒体断点的 `max-height: 45vh`
2. **滚动只能存在于 Shell.Body 一层**——子组件用 `flex: 1; min-height: 0` 让出高度。
3. **子组件用 fr / auto 定义内部分区**——外层 Shell 决定可用高度。
4. **关键操作不参与滚动**——主 CTA 始终位于 Shell.Footer 粘底，仅列表/详情区可滚。

### 4.3 大型工具切换形态

| 工具 | 形态 | 宽度规约 |
|------|------|----------|
| Banana / Custom | 右侧 USlideover | 桌面 420-520 px，全高 |
| Slicer | 居中 UModal | min(880px, 100vw - 28px) / 90vh |
| Sticker | 提升为页面 | （取消弹层） |

居中 UModal 仅留给"快进快出、视觉对称"的单次工具（Slicer），其内容是"原图预览 + 参数 + 九宫格结果"三块，居中弹层的对称感与之契合。

### 4.4 移动端策略

- USlideover 在 `<768px` 自动改为底部 Bottom Sheet（高度 90vh + 顶部拖拽条）
- 居中 UModal 在 `<768px` 改全屏 Sheet（已部分覆盖：`layouts/default.vue` 行 916-927 的媒体断点继续保留并扩展）
- Sticker 页面网格 `grid-cols-2`（≥md `grid-cols-3`，≥lg `grid-cols-4`），不再 4 列硬挤

## 五、设置入口处理

**删除死路由 `app/pages/settings.vue`**。理由：
- `pages/settings.vue` 仅是 `SettingsPanel` 组件的薄包装（与右侧抽屉用同一个组件实例），违反"唯一真相源"原则，未来改 props 必出 bug。
- 当前侧边栏与所有视图均无任何入口指向 `/settings`，删除无回归风险。
- 设置属于"伴随主流程"的全局偏好（命中 C5），右侧抽屉已是最佳形态。
- 若未来需深链到具体设置项，用 query 参数（如 `?panel=settings&tab=model`）即可，无需独立路由。

## 八、验证方式（端到端）

P0 / P1 完成后逐项验证：

1. **弹层显示不全修复验证**：
   - 在 1440×900、1920×1080、768×1024、375×667 四种视口下打开每个工具
   - 检查内容区是否撑满 Shell.Body、是否仅有一层滚动条、主 CTA 是否始终可见
   - 在 Banana 列表加载 200+ 条提示词、Custom 加载 100+ 条提示词时验证滚动流畅度
2. **Banana / Custom 改 USlideover 验证**：
   - 从侧栏点击工具卡 → 右抽屉自动打开、宽度合理、与设置抽屉互斥关闭
   - 选中提示词 → 抽屉关闭 → 内容已塞入主聊天输入框（验证 `chat-input-bridge` 路径不变）
3. **侧栏分组 + 微图标验证**：
   - 桌面/移动两种视口下分组标题与微图标正确显示
   - 点击 Chat / XHS / Sticker 走 NuxtLink 跳转；点击 Banana / Custom / Slicer 走弹层抽屉
4. **死路由删除验证**：
   - 直接访问 `/settings` 应进入 404 或重定向到 `/`，控制台无残留 warning
5. **Sticker 页面化验证（P2）**：
   - 关闭浏览器标签后重开，最近的批量生成结果仍可在历史中查看
   - 页面三区（角色配置 / 表情动作选择 / 结果队列）独立滚动，互不干扰
